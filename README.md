# 项目预算管理工作台 · Project Budget Workbench

单文件（`index.html`）的企业项目预算与成本管理工作台。零依赖、零后端，双击即可运行，也可直接部署为静态站点。

**当前版本：v1.0.1**

---

## 一、这是什么

把原来散在钉钉在线表格里的《项目预算管理表》搬进一个可交互的工作台：驾驶舱看全局，项目目录看进度，项目页按周录入工时与成本，系统自动算出人工成本、实际开发成本、项目毛利与纯利率。

- **技术形态**：单个 HTML 文件，内嵌 CSS / JS，无任何外部依赖与 CDN，断网可用
- **数据存储**：浏览器 `localStorage`（数据只在本机浏览器，不上传任何服务器）
- **运行环境**：Chrome / Edge / Safari / Firefox 等现代浏览器（不支持 IE）
- **适用规模**：中小团队内部使用，每人各自一份数据，通过「导出/导入数据备份」交换

## 二、角色与权限

| 角色 | 驾驶舱 | 项目目录 | 项目页 | 用户管理 | 基础数据 |
|---|---|---|---|---|---|
| **管理员 admin** | 全公司 | 全部项目 | 全部字段可编辑（含已回款金额） | ✅ | ✅ |
| **项目经理 pm** | 本人负责项目 | 本人负责项目 | 本项目可编辑（已回款金额除外） | ❌ | ❌ |
| **项目成员 member** | 参与的项目 | 参与的项目 | 仅可填写自己的工时 | ❌ | ❌ |
| **财务复核 finance** | 全公司 | 全部项目 | 仅成本项可订正，其余只读 | ❌ | ❌ |

**登录规则**

- 账号可用手机号，也可由管理员在「用户管理」里建自定义账号
- 手机号首次登录即自动注册为「项目成员」，**密码取你首次登录时输入的值**（长度不限；v1.0.1 起不再强制「手机号后 6 位」）
- 历史账号（v1.0.0 期间注册的）密码仍是手机号后 6 位，可直接用后 6 位登录，登录后自行修改
- 内置管理员：`admin / admin123`（首次部署后请立即修改密码）
- 登录后点右上角「修改密码」可自助改密，所有角色都可用；忘记密码可由管理员在「用户管理」中重置
- 权限按姓名匹配项目上的「项目经理 / 项目成员」字段，姓名需与项目目录中一致

## 三、账号与数据存储模型（重要）

单文件 + localStorage 的形态决定了下面这些边界，使用前请先确认符合你的协作方式：

| 场景 | 表现 |
|---|---|
| 同一台电脑、同一个浏览器内切换多个账号 | **共用同一份项目/基础数据**，只是权限不同（管理员看全部、项目经理看自己的、成员只能填自己的工时） |
| 不同电脑，或同一电脑的不同浏览器 | **各自独立**，互相看不到对方的数据（等于两套系统） |
| 换设备 / 换浏览器 / 清理浏览器数据 | 数据不会自动跟随，需要「导出数据备份」→ 在新环境「导入数据备份」 |
| 多人同时在线协作 | 不支持。没有服务端，无法并发同步 |

**结论**：这是一个「单机版 + 多角色权限」的工作台，适合一台设备上由一个人（或几个人轮流）维护全部数据；不适合作为多人各自在自己电脑上登录的协同系统。若需要「每个账号独立空间 + 跨设备同步 + 真正的身份校验」，需要接入后端（数据库 + 登录），属于另一个量级的改造。

## 四、功能地图

### 1. 驾驶舱

- **首行 5 张 KPI**：项目总数、合同总额、签单开发成本汇总、当前预估开发总成本、预估开发超毛利
  - 预估开发超毛利 = 签单毛利（合同额 − 签单开发成本）− 预估开发毛利（签单开发成本 − 预估开发成本）
- **各阶段项目数**：点击阶段直接跳转项目目录并筛选
- **项目更新进度**：按「距上次更新时间」排序，≥7 天标黄、≥14 天标红，用于催办项目经理更新
- **项目经理 / 商务经理项目数（按阶段）**：两张交叉表，带合计行
- **项目成员总工时及各项目分布**：横向色带 + 项目标签，一眼看出人力投在哪

### 2. 项目目录

搜索（编号 / 名称 / 客户 / 商务经理）+ 商务经理、阶段、项目经理三重筛选。
列表含合同额、签单开发成本、**当前开发成本**（超出签单开发成本时红底警示）与操作入口。

### 3. 项目页

| 区块 | 内容 |
|---|---|
| 基本信息 | 客户、商务经理、项目经理、阶段、合同额、签单开发成本、**当前已回款金额（仅管理员）**、项目成员 |
| 利润测算 | 人工成本、其他成本、实际开发成本、签单开发成本、项目毛利、项目纯利率（全部以「元」为单位，毛利为负时红色提醒） |
| 工时管理 | 预计开发时长（月，0.5 步进）→ 自动按周排期；按人员录入每周工时（0~5 天，0.5 步进）；付款旗帜；CSV 模板导入导出 |
| 成本项 | 住宿 / 差旅 / 补贴 / 风险金，按周直接填写；CSV 模板导入导出 |

**自动排期**：从项目开始时间起，每周 5 个工作日、跳过周末，表头显示为 `W1(11/12-11/18)` 形式。

**金额口径**

- 社保公积金 = 工资 × 0.249 + 120
- 人天成本 =（工资 + 社保公积金）÷ 21.75 ÷ 0.85
- 人工成本 = Σ（人天 × 该人员人天成本）
- 项目毛利 = 签单开发成本 − 实际开发成本
- 项目纯利率 = 项目毛利 ÷ 签单开发成本

### 4. 用户管理 / 基础数据（仅管理员）

- 用户管理：改姓名、调角色、删用户；姓名与项目上的项目经理/成员对齐即自动获得权限
- 基础数据：人员名称、职级、工资，社保与人天成本自动计算；支持批量导入导出 CSV
- 项目页「添加人员」为下拉选择，只选人员、职级自动带出

### 5. 数据备份

侧栏「导出数据备份 / 导入数据备份」为 JSON 全量备份（用户、项目、基础数据）。换电脑、换浏览器前请先导出。

## 五、快速开始

### 方式 A：本地直接打开

双击 `index.html`，用 `admin / admin123` 登录即可（登录后建议立刻在右上角「修改密码」改掉）。

手机号账号：输入手机号 + 你想要的密码，首次输入即完成注册（自动为「项目成员」），之后再用同一密码登录。

### 方式 B：发布到 GitHub Pages（在线访问）

1. 新建仓库，把本文件夹内容推送到 `main` 分支
2. 仓库 **Settings → Pages** → Source 选 `Deploy from a branch` → 分支 `main`、目录 `/ (root)` → Save
3. 约 1 分钟后访问 `https://<用户名>.github.io/<仓库名>/`

`.nojekyll` 文件已包含，避免 GitHub 用 Jekyll 处理静态文件。

> 注意：Pages 站点（`https://…github.io`）与本地双击 `file://` 打开属于两个不同来源，localStorage 不互通，等于两套独立数据。

## 七、版本与更新流程

版本号遵循 `主版本.次版本.修订号`（SemVer）：功能大改升主版本，新增功能升次版本，修 bug 升修订号。

**每次发版三步**

1. 改代码：`index.html` 顶部的 `APP_VERSION` 改成新版本号（侧栏与登录页会自动显示）
2. 同步 `VERSION` 文件，并在 `CHANGELOG.md` 顶部新增一节
3. 提交并打标签：

```bash
git add -A
git commit -m "feat: 本次改动说明"
git tag -a v1.0.1 -m "v1.0.1"
git push origin main --tags
```

在 GitHub 仓库的 **Releases → Draft a new release** 选中刚推的标签，即可生成带附件（zip）的正式版本页。

## 八、已知限制

- 数据存在浏览器本地，**不同电脑 / 不同浏览器之间不共享**，迁移靠「导出 / 导入数据备份」
- 同一浏览器内多账号共用一份数据，权限按角色区分（详见第三节）
- 清理浏览器数据会清空工作台数据，请定期「导出数据备份」
- 单文件应用，没有服务端：密码是前端明文校验，**不具备真正的安全防护能力**，请勿用它在公网承载敏感薪酬数据；如需真实鉴权与多端同步，需接入后端
- 密码本身不限长度，但也因此不设强度校验，建议 8 位以上
